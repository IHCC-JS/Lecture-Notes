# Video Reflection

Each lab will end with a 60-second video reflection.
This does not need to be a polished production; it is just a way for you to reflect on your work and share your thought process with me.
This reflection will be how I evaluate your understanding of your own code.
This video will only be viewed by me, so you can be as informal as you like.

### Video Requirements

- **Time Limit:** 60 seconds minimum, 2 minutes maximum.
- **Format:** Screen recording with audio and webcam.
- **Tools:** I recommend using [OBS Studio](https://obsproject.com/download) for recording. It’s free and works on all platforms. Microsoft also has some built-in screen recording tools.
- **Submission:** The best way to submit is to upload your video to a platform like YouTube (unlisted) or Outlook OneDrive and share the link with me. If you want to send the video file directly, you need to compress it to under 50MB using a tool like [HandBrake](https://handbrake.fr/).

### Presentation Structure

1. **Live Demo**
   Show the application running. Demonstrate all the primary features of the lab.
    - State the Status of the project: Is it 100% functional, or are there bugs? Be honest about the current state.
2. **Code Tour**
   Switch to your IDE. Briefly scroll through your classes or methods to show the project structure.
    - The Big Picture: Explain how the data flows at a high level (e.g., "This end point calls the service, which then maps the JSON to my POCO list").
3. **Deep Dive** Highlight **one specific block of code**.
    - Don't just read the code; explain _why_ it works that way. (e.g., "In this loop, I’m using a Try/Catch to handle potential null references when the user enters invalid data.")
4. **The Post-Mortem**
   Discuss the project's shortcomings or road blocks.
    - Reflection: What would you fix if you had another hour? What part of the syntax is still a bit fuzzy?
    - If you didn't get the project to 100%, explain what’s missing and why. Was it knowledge gaps, time management, or something else?

---

### Tips

- **Rehearse once:** 60 seconds is faster than you think. Don't try to explain every line of code; pick the part you are most proud of.
- **Resolution:** Ensure your code font size is large enough to read in the video.
- **Audio:** Make sure you aren't being drowned out by computer fan noise or background music.
